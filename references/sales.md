# Sales: users and transactions

Read-only views of who signed in or bought and what they paid, plus trial adjustments. Docs: https://docs.yard.sh/v1/platform/getting-started/yard-cli/users.md, https://docs.yard.sh/v1/platform/getting-started/yard-cli/transactions.md. Both read the project itself only: sandbox (simulated) sales and users never appear, and there is no `--sandbox` flag.

- `yard users list [--project <slug>] [--sort ...] [--json]`: everyone who signed in to a project or has a purchase of it that went through, refunded or not; a visitor who only saw the page or left a checkout is not listed. ACCOUNT is `yard` or `project` (a project account: one a user creates in that project, existing only there), JOINED the first sign-in or purchase, LAST the last order. Totals count completed, unrefunded orders, so someone who never bought, or whose only order was refunded, shows zeros; the summary counts every user, but its avg spend and repeat rate only those with an order. `--sort joined` works, and users with no orders sort last under `lastTransaction` and `firstTransaction` either way. A user is one project's: someone who signed in to or bought two of the team's projects is a user of each, with a row, an id and that project's totals for each, and the summary counts them once per project; without `--project` a PROJECT column names each row's project and `--sort projectName` works. `yard users show <user-id-or-email> [--project <slug>]` shows one user on their one project, with their account, joined date and last sign-in. Ids are the UUID the user's project knows them by, the same as that project's `X-Yard-User-Id` and webhooks' `user_id` (yard-auth.md); pass the whole id or the email, and add `--project` when the email is a user of more than one project (it is refused otherwise); a yard account and a project account of one project can share an email, and then only the id works. Money is pre-formatted text (`"$87.00"`); use transactions for arithmetic.
- `yard transactions list [--project] [--start] [--end] [--search] [--type] [--status] [--kind tier|product] [--json]`: `.items[]` with `amount_cents` (subtotal), `total_cents` (with tax) and `team_earnings_cents`. `.stats` covers the date range and `--project`; `--search`, `--type`, `--status` and `--kind` narrow the rows only. `yard transactions show <order-id>` (`order_xxxxxxxx` or the UUID) prints the address the receipt went to on a `receipt sent to:` line, and the JSON carries it as `receipt_email`; for a project account (yard-auth.md) it is the account's own address, and the buyer manages the purchase at yard.sh signed in with it (checkout.md).
- `yard transactions trial <order-id> --add-days N` (negative shortens; up to 365 either way): days are added to the current expiry, not today, so an expired trial can come back. A card-required trial's first charge moves with it, and ending it now charges the card, so the command asks first (`--yes` accepts; required without a terminal). The user is notified by email and in-app.
- A project account the team deleted (yard-auth.md, Deleting a project account) leaves `yard users list` and its id no longer finds a user, but its sales stay in `yard transactions` under the same `user_id`: the user shows as the receipt's address marked `(deleted account)` in the list, `show` and `trial`, and the JSON has `user_deleted: true` with the receipt's address as `user_email`. The refund of a period's unused part at the delete is partial: it shows on the sale and sends no refund webhook.
- The team's subscription API (read, cancel, resume or change one user's subscription) names the user by their project user id, the same value as `X-Yard-User-Id` and webhooks' `user_id`; an email is refused with `user_email_unsupported`. This changed: code that sent an email must send the id. Docs: https://docs.yard.sh/v1/api/subscriptions/get-subscription.md.
- Products the team gives a user (products.md) are not sales: they never appear in `yard transactions`, users' totals or the subscribers list. Giving and removing are on the dashboard only.
- Refunds: teams cannot issue them from the CLI or the dashboard; Yard support (support@yard.sh) does.
